# 2026-11-24 — Exact GGUF file sizing and ModelScope downloads

- The forward calculator reads public Hugging Face `blob` and `resolve` file links, or `org/repo filename.gguf`. It asks the Hub's `paths-info` API for bytes at the selected revision; a split GGUF is sized only when every part is present. Only metadata and config are fetched, not model weights. Repository import and manual model sizing remain available.
- File bytes replace the weight estimate, not the KV cache or activation allowance. The quant label is derived from the filename when recognizable. The existing architecture import uses `config.json` at the revision or the linked base model. If architecture is missing, the file size is still shown, and the calculator asks for layers, KV heads and head dimension before estimating total VRAM. No extra vision-encoder size is inferred.
- Only Copy share link puts the file source, exact bytes and architecture snapshot in the copied URL. The live address omits those values, and file results do not send a result analytics event. The recipient and link preview do not contact Hugging Face again. The file is not saved to the hardware profile.
- The config importer preserves separate global and sliding-window KV dimensions when the layer pattern is available. The Gemma 4 31B layout matches the indexed model, and the copied link and preview retain both sets of dimensions.
- Gemma 4 E4B shares KV caches across its final 18 layers. Following llama.cpp, only the first 24 layers count toward allocation, including just four global layers.
- Past the model's context limit, the calculator and share preview warn without claiming a fit or speed. The calculator still shows the raw memory estimate.
- Explicit auxiliary names such as vision projectors, draft heads, `mtp-head` and imatrix are rejected before metadata is requested. An MTP tag by itself is ambiguous: reject only when the file is less than a quarter the size of the equivalent non-MTP file in the same folder, if listed. Bundled model weights remain usable.
- Clearing the file restores the saved indexed model, quant and context. If the profile names a custom model, its architecture is not stored, so clearing leaves the picker empty without changing the saved model or estimating an unrelated default.
- Five indexed Chinese models show a ModelScope download link with the uploader named in both languages. See the [listing evidence and MiniMax exclusion](../data-corrections.md#2026-11-24--modelscope-gguf-download-links). No new routes, dependencies or backend work.
