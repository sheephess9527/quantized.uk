# 2026-11-23 quantized.uk patrol

Reviewed the recent and trending text-generation and image-text-to-text listings on
[Hugging Face](https://huggingface.co/models), 17 publisher feeds, the current
index and the candidates in `/pending/`. The starting main was `c6bc07a`, which
already included KORMo-Web-4B, the five frontier-model additions, model/GPU pairs
and the latest calculator filters. This patrol adds three entries, bringing the
catalogue to 160 models (140 active, 158 with licence data, 51 with image input).

## Added to the index

All three model cards declare Apache 2.0. Each new entry has bilingual text, a Hub
mapping, a licence record, a homepage feed entry and four sourced GGUF variants.
Sizes below are file bytes, excluding the separately listed projector.

| Model | Q3_K_M | Q4_K_M | Q5_K_M | Q8_0 |
| --- | ---: | ---: | ---: | ---: |
| KORMo-Web-9B | 4,480,146,240 | 5,841,050,432 | 6,886,087,488 | 9,527,499,584 |
| Granite Switch 4.1 8B | 5,474,645,792 | 6,412,400,416 | 7,214,561,056 | 10,096,444,096 |
| Granite Switch 4.1 30B | 17,512,331,648 | 21,035,547,008 | 23,954,782,592 | 34,047,264,032 |

- **KORMo-Web-9B.** The text GGUF Q4_K_M header has 8,953,803,264 stored
  parameters and `qwen35` architecture. The original config and header agree on
  32 layers, eight full-attention blocks, 16 attention heads, four 256-wide
  KV heads and 262,144 tokens. The BF16 projector is 921,705,120 bytes and is
  included when sizing image inference. The site-generated command starts
  text inference. Image inference needs the projector separately. The estimate
  excludes browser and extension overhead. [Publisher card](https://huggingface.co/KORMo-VL/KORMo-Web-9B) · [Config](https://huggingface.co/KORMo-VL/KORMo-Web-9B/blob/main/config.json) · [GGUF and projector files](https://huggingface.co/bartowski/KORMo-VL_KORMo-Web-9B-GGUF/tree/main) · [Pinned runtime Qwen implementation](https://github.com/ggml-org/llama.cpp/blob/b12409/src/models/qwen35.cpp)
- **Granite Switch 4.1 8B.** IBM's text GGUFs are distinct from the newer
  Granite 4.2 family and from IBM's speech pipeline. The Q4_K_M header has
  8,974,319,616 stored parameters including the two adapters, 40 transformer
  blocks and 131,072 tokens. The publisher's Transformers config lists a
  different block count. The GGUF estimate uses its own 40 blocks with
  32 query heads and eight 128-wide KV heads, plus llama.cpp's single-head
  128-wide K and V router cache for each token. The site offers llama.cpp
  for these files. Ollama support for their adapter architecture has not been
  verified. [Publisher card](https://huggingface.co/ibm-granite/granite-switch-4.1-8b) · [Config](https://huggingface.co/ibm-granite/granite-switch-4.1-8b/blob/main/config.json) · [Official GGUF](https://huggingface.co/ibm-granite/granite-switch-4.1-8b-GGUF/tree/main) · [Pinned runtime router implementation](https://github.com/ggml-org/llama.cpp/blob/b12409/src/models/granite-switch.cpp) · [Pinned runtime cache construction](https://github.com/ggml-org/llama.cpp/blob/b12409/src/llama-model.cpp)

- **Granite Switch 4.1 30B.** The publisher also released standard text GGUFs
  for the 30B checkpoint. Its Q4_K_M header reports 30,551,851,008 stored
  parameters and 64 blocks. It has the same 32 query and eight 128-wide KV
  heads, single-head adapter router and 131,072-token context as the 8B export.
  The GGUF estimate uses 64 blocks. IBM's original Transformers config lists
  66 layers. The same Ollama guard applies.
  [Publisher card](https://huggingface.co/ibm-granite/granite-switch-4.1-30b) · [Config](https://huggingface.co/ibm-granite/granite-switch-4.1-30b/blob/main/config.json) · [Official GGUF](https://huggingface.co/ibm-granite/granite-switch-4.1-30b-GGUF/tree/main)

File sizes come from the public Hub trees and Q4_K_M HTTP range response totals.
Tensor counts come from GGUF tensor shape products. The memory values are
estimates. This run had no GPU inference, quality or throughput measurements.

  [Publisher card](https://huggingface.co/sarvamai/sarvam-105b-1711) · [GGUF card and files](https://huggingface.co/Do0rMaMu/sarvam-105b-1711-GGUF)

  [Step-5 publisher](https://huggingface.co/stepfun-ai/Step-5-Preview) · [Step-5 GGUF](https://huggingface.co/smalinin/Step-5-Preview-GGUF) · [Raon GGUF](https://huggingface.co/KRAFTON/Raon-1-nano-gguf)

## Verification and deployment

The first application commit included KORMo and Granite 8B. The same-day
follow-up covers the publisher’s 30B variant after its GGUF header audit.

The first local build detected missing dependencies in the existing workspace.
Installed the current lockfile with `npm ci` before rerunning the checks.

- `npm test` passed, including 349 eligible model/GPU pairs, exact Windows
  filenames, the Granite router KV regression and both RSS languages.
- `npm run build` passed, including lint, type checking, static export,
  bilingual routes, 1,454 HTML files, 1,378 checked structured-data entities
  and 3,737 total files under the 15,000-file project cap.
- The HF build refresh returned 140 successful stats rows, including all three new
  models. Twenty unavailable responses did not remove existing rows.
- Both 390px Chromium flows passed on the final static export. Reviewed all three
  model pages, exact llama.cpp quant filenames and flags, copy and blocked
  clipboard fallback, Granite's runtime choice, the Arete Q3_K_M alternative
  (14.03 GiB at 4K), the reverse score filter, tutorial navigation, pending,
  benchmark versions, homepage dates and public release notes. Production
  browser probes block analytics requests.
- The local sitemap had 1,450 unique URLs. Both RSS feeds and the public
  160-model JSON contained the three additions and their expected file data.
