## Model additions

The index now contains **148 checkpoints**, 128 active, 146 with recorded
licences, and 42 with image input. All three additions are Apache 2.0.
Publisher configs and cards, licence files, GGUF tensor headers and tree
listings were read on November 19. Parameter counts below are for language
tensors in the selected quant files. All file sizes are exact bytes.

| Model | Stored language params | Decoder and main cache | GGUF tiers and bytes | Separate projector |
| --- | ---: | --- | --- | ---: |
| DaisyRose 27B | 27,320,697,856 | 64 decoder layers, 16 growing KV, 4 KV heads × 256 | Q3_K_M 13,325,853,504 · Q4_K_M 17,325,372,224 · Q5_K_M 20,787,639,104 · Q8_0 29,047,079,744 | F16 927,607,424 |
| Apex 35B V1.0 | 35,505,251,456 | 40 decoder layers, 10 growing KV, 2 KV heads × 256, 256 experts with 8 selected per token | Q3_K_M 17,821,288,672 · Q4_K_M 22,795,471,072 · Q5_K_M 27,461,634,272 · Q8_0 37,813,700,832 | F16 899,283,616 |
| Ternary Bonsai 2 27B | 26,895,998,464 | 64 layers, 16 growing KV, 4 KV heads × 256 | Official Q2_0 7,626,008,928 | Q8_0 629,246,976 |

All three advertise 262,144 context. DaisyRose and Apex tensors include one
MTP block. Ordinary decoding uses the main cache only. The calculator budgets
the full language file and does not size a separate speculative cache.
Apex expert parameters are 40 × 256 × 3 × 2048 × 512 = 32,212,254,720.
Both Apex weight and projector listings come from bartowski, whose Q4_K_M has
different bytes from the model author's conversion. For Bonsai, the official
Q2_0 file follows the upstream 18-byte-per-64-weight block format, includes
Hadamard metadata, and the publisher specifies llama.cpp b11556 or newer.
The published PQ2_0 and PTQ1_0 files need distinct kernels. This addition
covers Q2_0 only. The standalone and inline paths omit an executable Ollama
command for Bonsai because its handling of the Hadamard metadata remains
unverified.

At text-only 4K / batch 1 / f16 KV, the shared calculator returns 18.38
GiB for DaisyRose Q4_K_M, 23.91 GiB for Apex Q4_K_M and 8.24 GiB for
Bonsai Q2_0. These are estimates. No new peak-memory measurement, speed
figure or perplexity-loss percentage is published.
